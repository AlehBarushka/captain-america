# Капитан Америка

Семейный ипотечный калькулятор: дифференцированный график платежей в белорусских рублях (BYN) с учётом досрочных погашений. Это PWA без сборки на чистом JavaScript. Данные хранятся в Firebase и синхронизируются между устройствами членов семьи. Интерфейс на русском.

## Возможности

- График платежей на весь срок: остаток, проценты, основной долг, платёж, итог по месяцу.
- Три экрана на телефоне: **Платёж** (текущий месяц и кнопка «Оплатить»), **График** (карточки месяцев) и **Параметры** (сумма, ставка, срок, дата договора, итоги). На компьютере график показан таблицей.
- Три группы итогов: **План**, **Корректировка** (эффект досрочных погашений и экономия на процентах) и **Факт** (по оплаченным месяцам).
- Установка на домашний экран и работа офлайн для оболочки приложения (service worker).
- Вход по email и паролю, общий график для всех, кто вошёл.

## Как считается график

- **Банковский год** — 360 дней. Проценты за период: остаток × ставка / 100 × дни / 360.
- **Первый период** — по фактическим дням: со следующего дня после даты договора до конца этого месяца. **Все следующие месяцы** — по 30 дней, независимо от числа дней в календарном месяце.
- **Первые 12 месяцев** платятся только проценты. С 13-го месяца основной долг равен остатку, делённому на число оставшихся месяцев. Срок кредита не меняется.
- **Досрочный платёж** уменьшает долг со следующего дня после даты оплаты. До этой даты проценты идут по старому остатку, дальше по новому. После досрочного погашения платёж пересчитывается на оставшиеся месяцы, срок остаётся прежним.
- **Суммы в неоплаченных месяцах в расчёт не входят.** Введённое значение сохраняется и начинает учитываться после отметки «Оплачен» или кнопки «Оплатить».
- Деньги считаются в копейках (целые числа), итог по последнему месяцу закрывает остаток.

## Запуск

Нужен только Python 3 и браузер. Сборки и зависимостей нет.

```bash
cp .env.example .env
# заполните значения из Firebase Console → Project settings → Your apps → Web
python3 scripts/inject-firebase-config.py
python3 -m http.server 8080
```

Откройте `http://localhost:8080`. Service worker работает на `localhost` и по HTTPS.

Без конфигурации Firebase приложение откроется без входа и посчитает график, но ничего не сохранит.

## Firebase

1. Создайте проект и веб-приложение в Firebase, включите **Authentication → Email/Password** и **Cloud Firestore**.
2. Добавьте пользователей вручную в Firebase Console. Формы регистрации в приложении нет.
3. Опубликуйте правила из `firestore.rules.example`.
4. Данные лежат в одном документе: коллекция `family_schedule`, документ `main` (суммы, отметки оплаты, даты и параметры кредита).

Конфиг веб-приложения Firebase не является секретом, он попадает в браузер. Защищают данные правила Firestore и список пользователей, поэтому не оставляйте включённой самостоятельную регистрацию, если она не нужна: правила из примера пускают любого вошедшего пользователя.

Файлы `.env` и `js/firebase-config.js` находятся в `.gitignore`. Не коммитьте их.

## Публикация на GitHub Pages

Деплой запускается при push в `master` (`.github/workflows/pages.yml`). Шесть переменных `FIREBASE_API_KEY`, `FIREBASE_AUTH_DOMAIN`, `FIREBASE_PROJECT_ID`, `FIREBASE_STORAGE_BUCKET`, `FIREBASE_MESSAGING_SENDER_ID` и `FIREBASE_APP_ID` задаются в Settings → Environments → `github-pages` (как variables или secrets). Если хотя бы одной нет, джоб завершится с ошибкой и покажет, какой.

**Перед каждым push** меняйте версию кэша service worker:

```bash
python3 scripts/bump-sw-cache.py
```

Скрипт увеличивает `CACHE_VERSION` в `sw.js`. Включайте `sw.js` в тот же коммит, иначе клиенты могут получить старый HTML с новым JS.

## Структура

```
index.html                 разметка, три экрана, вход
css/styles.css             стили, мобильная вёрстка
js/app.js                  расчёт графика, интерфейс, Firebase
js/firebase-config.js      генерируется, в git не попадает
sw.js                      service worker, версия кэша
manifest.webmanifest       манифест PWA
scripts/                   генерация конфига Firebase, бамп версии кэша
firestore.rules.example    пример правил Firestore
.github/workflows/         деплой на GitHub Pages
```

## Технологии

HTML, CSS, JavaScript без фреймворков и сборки, Firebase (Authentication и Firestore, SDK 9 compat с CDN gstatic), GitHub Pages.
